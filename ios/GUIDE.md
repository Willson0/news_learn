# iOS «Карта Ликвидности» — полное руководство: установка, тесты, деплой

Нативное приложение на **Swift + SwiftUI**, повторяющее веб-фронт (`frontend/`)
один-в-один и работающее с тем же **Laravel**-бэкендом (`backend/`) по REST API.
Бэкенд не меняется — мобильный клиент лишь ещё один потребитель того же API, что
и веб.

Документ самодостаточный: от чистого Mac до приложения в симуляторе и до сборки
в TestFlight/App Store. В конце — что делать, **если Mac нет**.

## 1. Что потребуется

| Инструмент | Зачем | Где взять |
| --- | --- | --- |
| **macOS** (14 Sonoma или новее) | iOS собирается только на Mac | — |
| **Xcode 16+** | IDE, iOS SDK, симулятор | App Store / developer.apple.com |
| **XcodeGen** | генерирует `.xcodeproj` из `project.yml` | `brew install xcodegen` |
| **Homebrew** | чтобы поставить XcodeGen | https://brew.sh |

Цель развёртывания — **iOS 16.0**, то есть приложение пойдёт на iPhone с iOS 16 и
новее. Xcode‑проект **не хранится** в репозитории: он генерируется из
`project.yml` (так в git нет бинарного `.xcodeproj` и конфликтов).

Структура:
```
ios/
├── project.yml                 # описание проекта для XcodeGen
└── KartaLikvidnosti/
    ├── App.swift               # точка входа
    ├── Info.plist
    ├── Theme/                  # дизайн-токены (перенос tokens.css)
    ├── Icons/                  # движок SVG-иконок (1:1 с вебом)
    ├── Data/                   # API-клиент, модели, сессия, токен
    ├── Components/             # кнопки, поля, карточки, график, чаты
    ├── Navigation/             # Router + корневой экран
    └── Screens/                # 20 экранов (вход … админка)
```

## 2. Поднять бэкенд

Приложению нужен работающий REST API. Два пути.

### Вариант А. Локально на Mac (для разработки и тестов)
Нужны **PHP 8.2+** и **Composer** (проще всего — [Laravel Herd](https://herd.laravel.com)).
```bash
cd backend
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate --seed       # таблицы + демо-данные
php artisan serve                # http://localhost:8000
```
- Проверка: `http://localhost:8000/api/ping` → `{"status":"ok",...}`.
- Демо‑вход в приложении: **`demo@karta.app` / `password`**.
- Коды подтверждения (регистрация/восстановление) при ненастроенном SMTP пишутся
  в `backend/storage/logs/laravel.log` (строка «Код подтверждения»).

> **Вход через Telegram в мобильном приложении недоступен** (он работает только
> внутри Telegram). В нативном iOS‑клиенте вход — по email/телефону и паролю или
> через регистрацию. Кнопка «Войти с Yandex» — заглушка дизайна.

### Вариант Б. Сервер по HTTPS (прод/стенд)
Полный деплой бэкенда (и веба) одним Docker‑контейнером с автоматическим HTTPS —
в [`../deploy/README.md`](../deploy/README.md).

## 3. Сгенерировать проект и открыть в Xcode

```bash
brew install xcodegen            # один раз
cd ios
xcodegen generate                # создаёт KartaLikvidnosti.xcodeproj
open KartaLikvidnosti.xcodeproj
```
В Xcode выберите схему **KartaLikvidnosti** и симулятор (например, iPhone 15).

> Генерировать проект заново нужно после каждого изменения `project.yml` или
> добавления/удаления файлов. `.xcodeproj` можно спокойно удалять — он
> пересоздаётся.

## 4. Адрес бэкенда (`API_BASE_URL`)

Базовый URL API задаётся параметром сборки **`API_BASE_URL`** (должен быть
корректным URL и оканчиваться на `/api/`). По умолчанию —
`http://localhost:8000/api/`.

- **Локальный бэкенд в симуляторе:** хост Mac виден как обычный
  `localhost`/`127.0.0.1` (в отличие от Android‑эмулятора, где это `10.0.2.2`).
  С дефолтным значением и запущенным `php artisan serve` всё заработает
  из коробки. HTTP к `localhost` разрешён через `NSAllowsLocalNetworking` в
  `Info.plist`.
- **Другой адрес** (прод/стенд) — задайте одним из способов:

  Через `project.yml` (строка `API_BASE_URL:` в `settings.base`) — поправьте и
  выполните `xcodegen generate` заново:
  ```yaml
  settings:
    base:
      API_BASE_URL: https://ваш-домен/api/
  ```
  Через командную строку:
  ```bash
  xcodebuild -project KartaLikvidnosti.xcodeproj -scheme KartaLikvidnosti \
    -sdk iphonesimulator API_BASE_URL='https://ваш-домен/api/' build
  ```
  Через Xcode: таргет → **Build Settings** → найдите `API_BASE_URL` → впишите
  значение.

Прод‑бэкенд по HTTPS работает без дополнительных настроек ATS. Если указать
заведомо неверный адрес, приложение не упадёт — покажет ошибку «Нет связи с
сервером»/«Неверный адрес сервера».

## 5. Запуск в симуляторе и тестирование

1. Поднимите локальный бэкенд (шаг 2А).
2. В Xcode выберите симулятор iPhone и нажмите **Run (⌘R)**.
3. Пройдите сценарий приёмки:
   1. **Вход** `demo@karta.app` / `password` → главная.
   2. **Регистрация** нового аккаунта → экран ввода кода (код из
      `laravel.log`) → подтверждение → вход.
   3. **Главная**: лента, фильтр по инструменту.
   4. **Аналитика**: поиск, фильтры по статусу, открытие отчёта, «Открыть отчёт»
      (html в WebView), «Открыть график».
   5. **Сообщество**: список чатов, вход в чат, отправка сообщения.
   6. **Профиль**: подписка, отслеживаемые инструменты (сохраняются), «Данные
      аккаунта» → смена email/телефона/пароля, «Выйти из аккаунта».
   7. **Админ‑функции** (если аккаунт — админ, см. `backend/config/admin.php`):
      кнопка «+» на аналитике, создание/редактирование/удаление отчёта с
      загрузкой обложки и html, настройка чатов, список администраторов.

Сетевые запросы можно смотреть в Xcode (Debug navigator → Network) или через
`Console.app`.

## 6. Запуск на реальном iPhone

1. Подключите iPhone кабелем, в Xcode выберите его как устройство.
2. Таргет → **Signing & Capabilities** → включите **Automatically manage
   signing** и выберите свою **Team** (достаточно бесплатного Apple ID; тогда
   сборка живёт на устройстве 7 дней).
3. Чтобы сборка под устройство прошла, в `project.yml` нужно **разрешить
   подпись** (по умолчанию она выключена ради CI‑сборки под симулятор): уберите
   из `settings.base` три строки и перегенерируйте проект:
   ```yaml
   # удалить перед сборкой на устройство:
   CODE_SIGNING_REQUIRED: "NO"
   CODE_SIGNING_ALLOWED: "NO"
   CODE_SIGN_IDENTITY: ""
   ```
   ```bash
   xcodegen generate
   ```
   (Либо не трогайте `project.yml`, а переопределите эти настройки в Xcode для
   своей локальной сборки — но правка `project.yml` надёжнее, т.к. переживает
   регенерацию.)
4. Адрес бэкенда: реальный iPhone не видит `localhost` Mac’а. Соберите с
   `API_BASE_URL=http://<IP-Mac-в-сети>:8000/api/` (iPhone и Mac в одной Wi‑Fi,
   `php artisan serve --host 0.0.0.0`), либо используйте бэкенд по HTTPS.
5. Нажмите **Run (⌘R)**. При первом запуске на устройстве подтвердите доверие
   профилю разработчика: на iPhone Настройки → Основные → VPN и управление
   устройством → доверять.

## 7. Релиз: Archive, TestFlight, App Store

Нужен платный аккаунт **Apple Developer Program** ($99/год).

1. Разрешите подпись в `project.yml` (как в шаге 6.3) и перегенерируйте проект.
2. В [App Store Connect](https://appstoreconnect.apple.com) создайте приложение с
   вашим **Bundle ID**. По умолчанию это `app.karta.likvidnosti` — он должен быть
   уникален; при необходимости поменяйте `PRODUCT_BUNDLE_IDENTIFIER` в
   `project.yml`.
3. В Xcode: таргет → Signing & Capabilities → ваша Team, Bundle ID.
4. Впишите боевой **`API_BASE_URL` по HTTPS** (`project.yml` → `xcodegen generate`).
5. Поднимите версию/билд: `MARKETING_VERSION` (например, `1.0`) и
   `CURRENT_PROJECT_VERSION` (+1 на каждую загрузку) в `project.yml`.
6. Выберите destination **Any iOS Device (arm64)** → `Product → Archive`.
7. В открывшемся **Organizer** → `Distribute App`:
   - **TestFlight & App Store** → загрузка в App Store Connect; оттуда раздаёте
     тестировщикам через TestFlight или публикуете в App Store после ревью Apple.
   - **Ad Hoc / Development** → `.ipa` для ограниченного круга устройств.

Командная строка (альтернатива GUI): `xcodebuild archive` → `xcodebuild
-exportArchive` с вашим `exportOptions.plist`.

## 8. Если Mac нет

Собрать и запустить iOS‑приложение без macOS и Xcode нельзя — это требование
Apple. Варианты:

- **CI уже собирает проект** на GitHub Actions (`.github/workflows/ios.yml`,
  раннер `macos-15`): XcodeGen генерирует проект, `xcodebuild` собирает debug под
  симулятор. Это бесплатная проверка, что код компилируется, — но запустить и
  потыкать приложение так нельзя (артефакт не устанавливается на симулятор без
  интерактивной сессии).
- **Облачный Mac**: [MacStadium](https://www.macstadium.com),
  [MacinCloud](https://www.macincloud.com), AWS EC2 mac‑инстансы — аренда Mac с
  Xcode по RDP/VNC, дальше как в разделах 3–7.
- **Xcode Cloud** (встроен в App Store Connect) — сборка и раздача в TestFlight
  без своего Mac, настраивается из репозитория; но для первичной настройки обычно
  всё равно удобнее один раз открыть проект в Xcode.
- **Чужой/арендованный Mac** на один вечер: сгенерировать проект, собрать архив,
  выгрузить в TestFlight — дальше тестировать можно с любого iPhone.

Для чисто «посмотреть, как выглядит и работает интерфейс» без Mac проще всего
воспользоваться веб‑версией (`frontend/`) — она пиксель‑в‑пиксель совпадает с
нативной.

## 9. Диагностика типичных проблем

| Симптом | Причина / решение |
| --- | --- |
| `xcodegen: command not found` | Не установлен XcodeGen: `brew install xcodegen`. |
| Данные не грузятся, везде пусто | Неверный/недоступный `API_BASE_URL`. Проверьте `/api/ping` из браузера Mac. В симуляторе хост — `localhost`; на реальном iPhone — IP Mac в сети, не `localhost`. |
| «Нет связи с сервером» на реальном iPhone | iPhone не видит `localhost` Mac. Используйте IP Mac в сети + `php artisan serve --host 0.0.0.0`, либо HTTPS‑бэкенд. |
| Сборка под устройство падает на подписи | Не разрешена подпись в `project.yml` (шаг 6.3) и/или не выбрана Team в Signing & Capabilities. |
| Проект не открывается на старом Xcode | Нужен Xcode 16+ (формат XcodeGen object‑version 77). macos‑14/Xcode 15.4 его не читает. |
| HTTP‑запрос к своему серверу блокируется | Это не `localhost`, а другой домен по `http`. ATS разрешает только локальную сеть; боевой сервер должен быть по `https`. |

Сборка проверяется на CI при каждом пуше (`.github/workflows/ios.yml`): ошибки и
предупреждения компилятора собираются в отдельный блок в конце лога.
